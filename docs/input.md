# Pointer and touch input

Pointer geometry is distance-driven, not event-rate-driven. Raw pointer events are condensed into short spatial segments whose count depends on travelled bed distance rather than how frequently a mouse, trackpad, pen, or touch screen reports events. Real DOM timestamps remain attached to those segments, so gesture speed changes the simulated momentum and ejection response without changing the geometric distance covered by the tool.

Each fixed simulation step can consume several short contact segments. Under normal frame pacing all travelled geometry is retained. A pathological GPU stall is different: each pointer keeps only a small bounded amount of queued geometry—at most four rendered frames of maximum contact work—dropping the oldest stale samples if the browser keeps delivering touch input while rendering cannot advance. This bound is deliberately larger than one frame so normal fast strokes are never truncated merely because their spatial subdivision produces slightly more than one frame of contact segments. This prevents old touch geometry from replaying seconds later behind the finger. The granular solver treats sufficiently fast batched contact as an impact regime: the swept geometry is still rasterized once, but current segment velocity drives a narrow dynamic penetration term and a leading-edge ejection budget so batching no longer turns a violent stroke into a shallow one. A held pointer with no movement produces no contact.

Multiple pointer IDs are tracked independently. Touch, pen, and mouse contacts can coexist, and a fixed-size contact batch is shared by the solver each substep. The batch is converted into one per-cell contact field before transport, so multi-touch does not multiply the full granular solve by the number of fingers. Where contacts overlap, the strongest local contact supplies motion while the disturbed shell takes the maximum influence.

The canvas uses Pointer Events and `touch-action: none` so browser panning and pinch gestures do not steal drawing input. Each active pointer is captured independently until release or cancellation. Window blur, page hiding, and explicit reset cancel all active contacts.

Drawing audio follows the same coalesced Pointer Event samples as the physical stroke queue, but analyzes motion in CSS pixels so the procedural timbre remains consistent with the reference sound design across render resolution and DPR changes. Speed smoothing is time-based rather than event-count-based; faster motion raises body/air/grain energy, direction changes add short crunch transients, and pen pressure contributes where the device reports it. With multiple simultaneous contacts, one procedural worklet is driven by the strongest current gesture so audio cost stays constant rather than scaling with touch count. If a held pointer stops moving, contact audio releases after a short input-gap tolerance while the pointer remains captured, matching the simulation rule that a stationary held finger produces no new contact. Pointer release, cancellation, reset, blur, and page hiding also release the audio contact and preserve the worklet's soft settling tail.

During the reset wash, input is intentionally gated off. The canvas stroke queue is cancelled, the toolbar controls are disabled, and no new pointer or keyboard drawing contact is accepted until the retreat finishes. Pointer contacts that begin while locked remain quarantined until their matching up/cancel event. The post-reset enable timestamp rejects delayed pre-enable WebKit pointerdown events, and every accepted pointer generation records its own start timestamp so delayed move/up/cancel/lost-capture events from an older generation cannot corrupt a newly reused pointer ID. Pointer-event timestamps are normalized to the page performance timeline before they enter the stroke queue so WebKit timestamp-origin differences cannot create pathological velocities. Drawing is re-enabled at the audio endpoint in the same turn that submits the final dry frame. If the GPU is still busy, the fixed-step clock retains elapsed time across skipped RAFs and performs only its normal bounded catch-up on the next accepted frame; GPU backpressure must never reset the clock and leave touch geometry replaying behind the finger. Coalesced pointer samples whose timestamps fail to advance are treated as missing timing data rather than as near-zero-duration impacts, avoiding the extreme fake velocities that WebKit can otherwise produce after a hitch.

Keys 1–9, 0, - and = select finger, rake, broom, trowel, wind, shell, feet, dig, bucket, pour, drip, and water; K selects the knife. The tool is latched per pointer at pointer down. Deposit tools (pour, drip, water) are routed to the pourer or water thrower, and dig and bucket to the earthworks, instead of the stroke queue. A bucket tap places its mold at pointer down; the mold chooser appears above the toolbar while the bucket is selected. A shell tap is the one deliberate exception to "a stationary press produces no contact": it enqueues a time-limited press independent of pointer motion. See `tools.md`, `water.md`, `symmetry.md`, `zen-garden.md`, and `history.md`.

Global shortcuts: Ctrl/⌘+Z undo, Ctrl/⌘+Shift+Z or Ctrl/⌘+Y redo, S or Ctrl/⌘+S save image, M cycle symmetry, G toggle the zen garden, W open the message writer, T cycle the sand (beach or a kinetic color), L cycle the time of day. While the message field has focus, every shortcut, Ctrl/⌘+Z included, belongs to the text field. Mouse hover (no buttons held) shows the tool outline; the rake's outline follows a smoothed hover heading.
