# Audio

The beach ambience uses `public/scene_assets/beach.mp3` as a quiet looping bed. All voices—ambience, reset wave, procedural contact, splash, and thud—pass through one master gain before reaching the Web Audio destination. Voice gains retain their individual levels, including the canonical `0.08` ambience level. The media elements stay at unity because iOS WebKit has historically ignored or inconsistently applied `HTMLMediaElement.volume`, which can otherwise make the beach track much louder on iPhone than on desktop. The game makes a best-effort playback attempt during scene startup when sound is enabled and the page is visible. If browser autoplay policy blocks that attempt, the first pointer or keyboard gesture resumes the already-prepared audio graph and starts the loop.

`SandSound.muted` and `setMuted(boolean)` are the control contract. The user's choice is persisted in `tidewrit.audio.muted`; unavailable or full storage does not disable the controls. A saved mute initializes the master gain at zero before any voice is connected. Muting immediately closes the master gain, pauses media, closes the procedural gesture gate, and requests context suspension. Unmuting calls both context resume and media playback synchronously, preserving browser user activation even while a preceding suspend is still pending.

Hidden pages also close the master gain, pause media, clear gesture state, and suspend the context without changing the saved mute preference. Returning to a visible page restarts ambience only when sound is enabled. Interrupted reset waves are not replayed; their visual animation proceeds on its existing clock. Failed automatic resume attempts remain eligible for retry at the next real pointer or keyboard gesture.

On iPhone/iPad-class devices, when the Audio Session API exists, the page requests the `playback` session before creating the shared `AudioContext`. This keeps the procedural Web Audio effect on the same audible playback route as the beach ambience instead of allowing the Ring/Silent state to mute only the procedural part of the mix.

The sand-contact sound is procedural and runs in one `AudioWorklet`, preserving the synthesis and finishing chain from `refs/procedural_sand_drawing_sfx.html`. The AudioContext, worklet module, and node graph are prepared during scene boot before drawing input is enabled. This is important for first-contact audio: a drawing gesture never has to wait for `AudioWorklet.addModule()`, and restricted browsers only need to resume the prepared context inside the pointer gesture. Gesture analysis is performed from the same coalesced Pointer Event stream used for drawing, so duration, speed, turns, and pen pressure affect the sound without coupling audio behavior to GPU frame rate or simulation backlog. A single strongest-gesture mix is used for multi-touch to keep the real-time audio workload bounded.

The reset wash uses `public/scene_assets/wave.mp3` through the shared `AudioContext`. Its dedicated voice gain keeps mobile Safari and desktop aligned. Reset animation timing uses the file's loaded metadata regardless of whether sound is muted. Metadata readiness can delay boot by at most 1500 ms; unavailable metadata leaves the measured 4.754-second fallback duration in place. Late metadata updates subsequent reset durations. Disposal cancels the metadata wait and removes its listeners.

Audio graph and lifecycle tests use lightweight Web Audio and media fakes. They cover every voice's route through the master gain, persistent startup mute, synchronous unmute during pending suspension, visibility transitions, reset duration while silent, blocked storage, bounded metadata readiness, and disposal. Browser autoplay policy and physical device audio routing still require listening on the target devices.
